# Смена пароля пользователя администратором

Дата: 2026-06-15

## Цель

Дать администратору возможность задать новый пароль любому пользователю через
админку (`/admin/users`), не зная текущего пароля.

## UX

Отдельное действие «Пароль» в колонке «Действия» строки пользователя (рядом с
«Изменить»). Открывает небольшую модалку `PasswordModal` с двумя полями:
«Новый пароль» и «Повтор пароля». Клиентская валидация: длина ≥ 6 символов и
совпадение полей. На успехе модалка закрывается; список пользователей не
обновляется (пароль нигде не отображается).

## Backend

Новый эндпоинт в [admin.ts](../../../backend/src/routes/admin.ts), под тем же
`requireAuth, requireAdmin`, что и остальные admin-ручки:

- `PATCH /api/admin/users/:id/password`, тело `{ password }`.
- Валидация:
  - пользователь существует — иначе `404 { error: "User not found" }`;
  - `password` присутствует и длиной ≥ 6 — иначе
    `400 { error: "password must be at least 6 characters" }` (паритет с
    созданием пользователя).
- Хеширование через `bcrypt.hash(password, SALT_ROUNDS)` (константа уже есть в
  файле), обновляется **только** поле `passwordHash`.
- Ответ: `204 No Content` (тело не возвращается — пароль/хеш наружу не отдаём).

Существующий `PATCH /api/admin/users/:id` **не меняется** — пароль он не трогает,
смена пароля живёт отдельным эндпоинтом.

## Frontend

- [adminApi.js](../../../frontend/src/services/adminApi.js): новая функция
  `changeUserPassword(id, password)` →
  `request(\`/api/admin/users/${id}/password\`, { method: "PATCH", body: { password } })`.
- [AdminUsersPage.jsx](../../../frontend/src/components/AdminUsersPage.jsx):
  - кнопка «Пароль» (класс `admin-table__action-btn`) в колонке «Действия»;
  - новый компонент `PasswordModal` в том же файле, по образцу `UserModal`
    (бэкдроп, `admin-modal__*` классы, состояние saving/error);
  - на успешном `changeUserPassword` — закрытие модалки. Список `users` не
    трогаем.

## Вне scope (YAGNI)

- Инвалидация активных сессий пользователя: уже выданные httpOnly-cookie
  (access 15m / refresh 30d) продолжают действовать до истечения. При
  необходимости — отдельной задачей.
- Требование текущего пароля: администратор задаёт пароль без знания старого —
  это и есть цель функции.

## Проверка

- `tsc --noEmit` в `backend/`.
- `npm run build` во `frontend/`.
- Ручной E2E: войти админом → `/admin/users` → «Пароль» → задать новый →
  выйти и войти этим пользователем с новым паролем.
